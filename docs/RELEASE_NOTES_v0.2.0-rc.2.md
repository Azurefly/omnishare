# OmniShare v0.2.0-rc.2 · 协同稳定性修复候选版

**本版从已合并统一工作区及后续修复的 main 重新构建。** 程序、前端、桌面壳和安装器的内部版本统一为 `0.2.0-rc.2`，不是 RC1 安装包改名。原有 Release 和标签保持不变，本版标记为 Pre-release，不替换稳定版 Latest。

## 相比 RC1 的修复

- 协同文档：阻止迟到的刷新响应覆盖已保存的新版本，当前编辑器刷新不再等待其他设备的慢列表。
- 草稿保护：加载远端或另存副本时保留请求期间的新输入；冲突后取消过期自动保存；另存副本防重复点击。
- 远端缓存：写入前后失效该设备缓存，拦截过期在途响应，避免已删除内容在离线列表中重新出现。
- 文件和视频：使用独立的长传输超时，不再套用普通 JSON 接口 18 秒超时；不盲目重试结果不确定的写入。
- 聚合排序：按实际 RFC3339 时间处理时区和小数秒。
- 设备发现：修正 Tailscale 扫描取消分支，移除旧单地址汇总逻辑。

## 统一工作区的使用方式

两端升级后，在任意一端选择“添加设备并合并工作区”，填写对方的内网或 Tailscale 地址及实际端口；只有对方启用保护时才需要填写其密钥。成功绑定后双方自动登记，工作台、随手记、文件/视频、协同文档、分享、回收站和活动记录合并展示，操作写回内容所属设备，不必打开另一套应用页面。

同一设备的内网 IP 和 Tailscale IP 按设备身份合并。发现设备不等于自动授权绑定；局域网采用组播，Tailscale 读取本机客户端的可见节点，不要求管理 API Key。自定义端口和 HTTPS 可手动填写。网络仍受防火墙、Tailscale ACL 和系统局域网权限限制。

新建内容默认保存在当前设备。聚合只包含直接绑定设备，不递归读取第三节点，不复制数据库和所有文件。配置、备份、恢复仍针对当前节点；离线快照不等于离线编辑。文档采用版本化保存和约 2 秒前台刷新，不是字符级 CRDT。

## 验证边界与已知限制

**这是候选版，不能将构建成功视为三平台安装使用全部通过。** 本次具体结果由构建结束时写入发布正文和 `build-manifest.json`，各平台的 `build-evidence-*.json` 保留真实的成功、失败、超时或未测试状态。

上一轮 Windows MSI 安装、注册及快捷方式检查成功，但原生 WebView 调试连接超时；Ubuntu 原生界面检查失败并留下黑屏截图。未解决项继续保留在 [Issue #36](https://github.com/Azurefly/omnishare/issues/36)，不能断言只由测试环境引起。本次重新执行相应检查，以新的结果为准。

macOS Universal 构建、ad-hoc 完整性签名及打包后端 HTTP 检查不等于原生窗口首装验收，也不等于 Developer ID 签名或 Apple 公证。**本版尚未完成 Apple 公证，仍可能出现系统阻止打开；不能保证首次下载后直接打开。** 不关闭系统安全保护，也不把其他平台的浏览器测试当成 macOS 实体机验收。

真实双实例浏览器测试运行于 Linux 构建机，不替代跨实体 Windows/macOS 与 Tailscale 网络验收。下载后请核对 `SHA256SUMS.txt`，按报告评估候选包。

## 升级与数据安全

升级前备份数据并完全退出旧应用和后端。保留原数据目录与配置，不需要删除数据库；双方都应升级。本次不执行数据清空或迁移覆盖。

新安装默认局域网开启、密钥保护关闭，无需 init Token；升级保留原设置。免密实例的访问者也能操作其合并工作区，只绑定可信设备，不要映射到公网。可按需开启访问密钥。普通内网 HTTP 不加密，不可信网络使用 HTTPS 或 Tailscale。
