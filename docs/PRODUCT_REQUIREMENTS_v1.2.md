# OmniShare 产品需求扩写 v1.2

## 1. 产品定位

OmniShare 是面向个人、家庭、小团队、研发现场和内网环境的私有化内容中枢。核心任务是让用户在多设备间快速收集、读取、分享、恢复和管理文本、文件、视频与轻量文档，同时保持部署简单、数据可控和离线可用。

它不应退化为：

1. 只能上传下载的网页文件柜；
2. 需要用户理解 IP、端口和 JSON 的技术工具；
3. 宣称实时协同但不能处理冲突的伪协作产品；
4. 用一个全局密码解决所有权限问题的高风险应用；
5. 只在开发机上能构建、没有正式交付链的样例项目。

## 2. 产品原则

1. **数据不丢优先**：误删、覆盖、过期、冲突和迁移均有恢复路径。
2. **本地优先**：核心能力不依赖外部 SaaS 或公网。
3. **默认安全**：管理权限与临时分享分离，敏感能力最小授权。
4. **三步可用**：安装、启动、同网访问不超过三个主要动作。
5. **诚实定义能力**：乐观锁不是实时协同，浏览器壳不是完整原生客户端。
6. **可验证交付**：每个发布版本有源码、构建、测试、安装包、校验值和限制说明。

## 3. 核心用户

- 个人多设备用户：电脑、手机、平板间传文字、链接、图片和文件。
- 家庭与小团队：共享局域网资料、临时链接和会议文档。
- 内网研发与运维人员：在不能使用公网网盘时传递日志、安装包和配置片段。
- 演示与现场人员：快速播放视频、展示文档、给访客提供受控下载。
- 管理员：控制容量、保留周期、访问密钥、备份和审计。

## 4. 关键业务流程

### 4.1 快速收集

复制内容 → 打开 OmniShare → 粘贴/识别标签 → 设置有效期或阅后即焚 → 发布 → 其他设备立即读取。

### 4.2 安全分享

选择内容 → 设置有效期与最大访问次数 → 生成独立链接 → 复制给接收者 → 查看访问次数 → 随时撤销。

### 4.3 安全删除

删除内容 → 进入回收站 → 在保留期内恢复或永久删除 → 到期自动清理 → 审计记录可追溯。

### 4.4 文件传输

选择或拖拽文件 → 显示进度 → 服务端计算摘要 → 重复文件复用 → 完成后下载/播放/分享/重命名。

### 4.5 文档协作

创建文档 → 自动保存 → 携带版本号提交 → 检测版本冲突 → 提示重新加载或人工合并 → 可分享只读版本。

## 6. v1.2.0 实施范围

本次不追求功能数量最大化，只处理最影响正式使用的能力：

1. 回收站及恢复/永久删除；
2. 回收站保留周期；
3. 对象级安全分享；
4. 分享有效期、访问次数、撤销和审计；
5. 文件 SHA-256 去重；
6. 文件重命名；
7. 统计看板增加分享与回收站；
8. UI 增加安全分享和回收站工作区；
9. GitHub Actions 和仓库治理文件；
10. 扩展单元、API、前端、跨平台和 E2E 测试。

## 7. 非功能指标

- 1 万条随手记/文档元数据下，列表查询目标小于 500 ms；当前 JSON 存储需在达到该规模前迁移索引型存储。
- 单文件默认上限 4 GB，可配置；当前 HTTP 上传在超大文件和弱网下仍有失败风险。
- 所有管理 API 必须经过访问密钥校验；公开分享仅允许访问指定对象。
- 删除文件在回收站期内必须保留实体，永久删除后实体不可残留。
- 所有写操作必须在崩溃后保持元数据 JSON 可解析。
- 发布包必须能从干净源码离线构建，不提交运行数据、密钥和用户内容。

## 8. v1.2.0 验收标准

- 三类对象删除后不再出现在正常列表，但出现在回收站；恢复后重新可用。
- 永久删除文件后磁盘实体消失。
- 分享链接在无全局访问密钥时可读取指定对象，不能访问其他管理 API。
- 达到访问次数、到期或撤销后，分享返回 HTTP 410。
- 重复上传相同内容返回同一个文件 ID，磁盘不产生第二份实体。
- 文件重命名后下载内容和摘要不变。
- 六个平台二进制成功生成且格式、架构和包结构正确。
- 五轮测试脚本最终输出 `ALL 5 ROUNDS PASSED`。
