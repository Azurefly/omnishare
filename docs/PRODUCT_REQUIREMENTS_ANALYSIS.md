# OmniShare 当前需求分析与产品补全结论

## 1. 原始项目判断

上传版本已经具备“随手记 + 文件上传 + 视频播放 + 协同记事板 + 设备列表”的原型，但存在三个根本问题：

1. **源码不可复现**：Go 代码中 `StartRegister` 调用与函数签名不一致；依赖需要联网下载；前端 `node_modules` 是 Windows 产物，在 Linux/macOS 无法构建。
2. **文档超前于实现**：文档声明分片上传、Faststart、tsnet、PWA、权限等能力，但代码没有对应实现，存在产品宣传与实际交付不一致。
3. **缺少正式产品闭环**：没有搜索、编辑、批量或筛选、统计、审计、备份、安全、健康检查、规范化测试、跨平台安装与干净源码交付。

## 2. 用户核心场景

- 手机与电脑之间快速传递文本、命令、链接和代码片段。
- 在局域网或 Tailscale 内上传文件，其他设备随时下载或在线播放视频。
- 多设备维护临时文档，避免覆盖他人的新版本。
- 在内网环境以最少依赖安装，能够备份、清理、审计和限制访问。

## 3. 本轮补充的必备能力

### P0：可交付与可运行

- 去除运行时第三方依赖，Go 标准库即可构建。
- 前端改为零依赖静态构建，不再携带跨平台不兼容的 `node_modules`。
- 源码与运行数据分离；清理旧 EXE、数据库 WAL、上传样例和缓存。
- 健康检查、优雅停机、原子写入、上传大小限制、文件名与路径隔离。

### P0：核心业务闭环

- 随手记新增搜索、标签筛选、编辑、置顶、TTL、阅后即焚和最大读取次数。
- 文件新增搜索、分类、TTL、SHA-256、HTTP Range、上传进度、实体删除。
- 文档新增搜索、自动保存、版本检查和 409 冲突保护。
- 新增统计看板、审计记录与完整 ZIP 备份。

### P1：多设备与安全

- 本机多网卡地址展示。
- 局域网 UDP 多播自动发现。
- 识别 Tailscale `100.64.0.0/10` 地址。
- 支持手动添加 MagicDNS、Tailscale IP 或跨网段节点并进行健康探测。
- 可选访问密钥，使用常量时间比较，避免最基础的时序泄漏。

### P1：多端安装

- 六个目标二进制：Windows/Linux/macOS × amd64/arm64。
- Windows：免管理员安装到 LocalAppData，创建桌面和开始菜单快捷方式。
- Linux：用户级安装脚本、桌面入口、amd64/arm64 `.deb`。
- macOS：Intel/Apple Silicon `.app` 包。
- Web/PWA：浏览器内可安装为独立窗口应用。

## 4. 本轮没有虚假宣称的能力

以下仍属于后续版本，不应视为已完成：

- 真正的分片上传、断点续传和秒传去重。
- ffmpeg Faststart 重排、转码和缩略图生成。
- CRDT/OT 级多人光标与离线合并；当前是版本冲突保护，不是实时协同算法。
- Tailscale API/tsnet 自动枚举整个 Tailnet；当前通过本机地址识别和手动节点完成跨网段连接。
- TLS 自动证书、细粒度账户体系、分享链接一次性令牌。
- Windows/macOS 商业代码签名与应用商店发布。

## 5. 下一阶段建议

v1.2 优先补齐分片上传、分享令牌、回收站、备份恢复、二维码快速加入节点；v1.3 再引入 CRDT 协同、缩略图/转码、Tailnet 自动节点目录和正式签名发布流水线。
