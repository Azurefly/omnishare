# OmniShare v0.1.0 发布说明

发布日期：2026-11-07。

OmniShare `0.1.0` 将当前后端、Web 和 Windows/Linux 桌面统一为一个产品基线，提供自托管的随手记、文件与视频、受控分享、轻量协作文档、设备发现、审计、备份恢复和回收站。

**本次应用版本号重新起算。** `0.1.0` 在安装器和包管理器的版本顺序中低于此前的 `1.x`，不能依赖自动升级。现有功能与数据格式继续保留，新加密备份仍使用 v3。已有安装请按本文的迁移步骤操作。

## 当前功能基线

### 工作区与内容发送

- 桌面左侧集中导航、设备与存储，右侧为当前模块；移动端保留连接状态和可滚动导航。
- 主题提供浅色、深色和跟随系统，设置按用途分组，统一图标、间距、焦点和状态文字。
- 剪贴板从用户点击开始读取，展示纯文本或 PNG、目标节点与保留时长；确认后才发送，默认保留 24 小时。
- 文件队列区分排队、上传、服务端处理、完成、失败和取消，支持手动重试与清理记录；重试也受最多 3 个并发限制。
- 设备按当前节点、在线和离线分组；发现与在线状态不代表访问授权，打开其他节点需要独立验证。

### 存储与恢复

- 默认 SQLite WAL，支持旧 JSON 备份后迁移与校验，已有 SQLite 数据库无法打开时明确停止。
- 受限阅读与阅后即焚同步消费次数并持久化，普通计数批量落库，备份包含未刷盘计数。
- v3 加密备份认证包头、分块顺序与结束记录，拒绝截断和尾随数据，兼容恢复 v2 与 ZIP。
- 恢复先解压校验，再切换配置、状态与文件；失败时回滚到切换前状态，上传使用空闲超时。
- 会话存储不可用时退回页面内存，文档保存失败或冲突时保留最新草稿；恢复防重复提交，备份下载失败时停止读取与写入。

### 访问与桌面

- 默认仅监听回环地址，本机初始化令牌用于首次配置，开启局域网前要求至少 16 字节的访问密钥。
- 管理密钥使用派生值存储，不放入 URL 或浏览器长期存储；内容下载和媒体使用短时票据。
- 桌面启动交接自有后端初始化令牌，提供单实例、托盘、端口避让、已有服务连接与后端异常恢复。

## 迁移到 0.1.0

1. **备份现有数据。** 在旧程序导出备份并保存口令，记录实际数据目录；如果保留完整目录副本，先完全停止服务，再复制数据库、文件和配置。
2. **退出旧进程。** 从桌面托盘完全退出，确认旧后端不再占用数据目录。不要在迁移时运行两个写实例。
3. **处理版本号重置。** `0.1.0` 不是包管理器意义上的递增升级，安装器可能拒绝覆盖。必要时先卸载旧应用，保留数据目录和独立备份，再安装新版本；不要执行清理用户数据的操作。
4. **明确使用原路径。** 沿用同一启动方式，或通过 `OMNISHARE_DATA_DIR` / `--data-dir` 指向原目录的绝对路径。检查访问配置和内容，确认数据齐全后再恢复日常使用。

| 原启动方式 | 通常的数据位置 |
| --- | --- |
| Windows Tauri 桌面或直接运行后端 | `%USERPROFILE%\.omnishare` |
| Windows ZIP 启动/安装脚本 | `%APPDATA%\OmniShare` |
| Linux Tauri 桌面、直接运行后端或服务器 DEB | `~/.omnishare` |
| Linux tar.gz 的用户级安装脚本 | `${XDG_DATA_HOME:-$HOME/.local/share}/omnishare` |
| macOS 后端 `.app` 或直接运行后端 | `~/.omnishare` |

配置过路径的环境以实际启动参数为准。桌面端和直接运行后端支持 `OMNISHARE_DATA_DIR`，后端的 `--data-dir` 可明确指定目录；包内安装脚本会传入自己的数据目录。

首次打开旧 JSON 数据时会先备份、再导入 SQLite。本次版本重置沿用当前 SQLite 数据格式，不会因为应用版本号较小而回退到旧 JSON。未设置密钥的环境使用本次启动提供的初始化链接；已经设置密钥的环境继续使用原密钥。

上述迁移不保证兼容任意历史数据库。早期写入 `backend/data` 的 SQLite 原型没有自动转换工具，应保留原程序和完整数据目录，在副本上另行转换与验证，不要直接覆盖唯一数据副本。

更新后如仍显示缓存的旧页面，可关闭其他 OmniShare 标签页并重新加载。当前页面的剪贴板预览、传输队列和仅存在于内存中的草稿不会跨刷新恢复，应先完成相关操作或复制重要文本。

## 备份兼容与恢复影响

| 格式 | 0.1.0 支持 |
| --- | --- |
| v3 `.osb` | 默认加密导出格式，可读取恢复。 |
| v2 `.osb` | 可读取恢复已有备份，不提供 v3 的完整包头和结束记录认证。 |
| 明文 ZIP | 可导出与恢复，内容没有加密。 |

备份格式版本独立于应用版本。`0.1.0` 支持 v3，不能根据版本号较小推断不兼容，也不能推断其他程序只因版本号较大就能恢复 v3。

加密口令不会保存在数据目录，丢失后无法恢复。v3 数据内容经过加密，版本、算法、创建时间与校验清单等包头元数据仍可读。

恢复成功会用备份替换当前数据和配置，备份后新增内容也会被替换。恢复前导出当前备份并暂停其他写入；解压阶段仍可读写，最终切换前成功的新写入也可能被目标备份覆盖。普通内存缓冲下载最多 2 GB，更大备份需要支持流式保存的浏览器；导出与恢复还受节点 `backup_max_mb` 配置约束。

## 安全与使用限制

- 剪贴板不后台监控，不自动发送；文本最多 256 KB，PNG 最多 16 MB，且受节点上限及解码尺寸限制。发送仅面向当前节点。
- 取消或中断上传不能撤回服务器已经保存的数据，重试前应检查列表。上传没有分片断点续传；HTTP Range 用于下载与视频。
- 当前为单管理员密钥模型，没有逐设备权限、可信配对、接收审批或端到端加密传输，也不提供系统键鼠控制与音频共享。
- 协作文档使用版本冲突检测，没有 CRDT/OT 实时合并；普通计数批量保存，进程崩溃可能丢失最近几秒计数。
- 清除访问密钥或恢复无密钥配置后的初始化令牌续发尚待完善，可能需重启后使用新的初始化链接；自动清理与恢复的文件协调、审计锚点完整备份恢复仍需后续改进。
- Windows 托盘、macOS 权限和 Gatekeeper，以及 Safari 和各种触屏设备仍需平台真机验收。发布物尚未提供商业代码签名、完整 SBOM 或来源证明。

更多行为说明见[安全共享与使用边界](https://github.com/Azurefly/omnishare/blob/main/docs/SECURE_SHARING.md)。
