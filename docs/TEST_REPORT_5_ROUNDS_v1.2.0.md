## 7. 测试中发现并修复的问题

1. **REST 详情缺口**：缺少随手记详情 API，请求落入前端 SPA 兜底页；已增加标准详情路由和测试。
2. **五轮脚本版本滞后**：发布包校验仍引用 v1.1.0 文件名；已统一为 v1.2.0。
3. **测试断言与审计模型不一致**：E2E 原断言使用不存在的 `share.consume` 动作；已按实际 `action=access, object=share` 验证。
4. **交叉构建执行时间**：串行六目标构建容易超过单次执行窗口；改为并行构建，并验证六个产物全部存在且非空。
5. **旧测试证据混淆**：移除当前目录中的 v1.1.0 日志，把旧报告归档。

## 8. 已知限制与风险

- 当前大文件仍为单请求上传，没有分片、暂停和断点续传；
- 分享链接尚无独立密码、二维码和端到端加密；
- 文档为乐观锁自动保存，不是 CRDT/OT 实时协同；
- JSON 存储适合个人和小团队，达到高并发或大规模元数据前应迁移 SQLite/PostgreSQL；
- HTTP 服务只适合可信局域网或加密隧道，不应裸露公网；
- Windows/macOS 包未代码签名，且仍需目标实体机安装冒烟测试；
- 尚无 v1.1.0 以前 SQLite 数据的自动迁移工具。

## 9. 结论

OmniShare v1.2.0 已达到本轮定义的内部发布标准：

- 需求与实现边界一致；
- 删除可恢复，分享可限制；
- 核心 API 和业务流程可重复验证；
- 六平台二进制与八类安装包可生成；
- 五层质量关卡全部通过。

它仍不是完成代码签名、可信设备配对、端到端加密、断点续传和实时协同的商业正式版，这些能力已进入版本化需求池，不计入本轮已完成范围。
