# OmniShare v1.3.0-rc1 发布说明

## 发布结论

本版本是对 v1.2 深度评审的安全与可靠性重构，定位为 **Release Candidate**，不是稳定版或商业正式版。150 条评审项中，主要安全发布阻断已整改，但单 JSON 存储、角色权限、自动 TLS、Windows/macOS 实机与供应链签名仍未完成。

## 关键修复

- 安全默认、密钥派生存储、禁止 URL 密钥、CSP/CORS/Host 防护。
- 短时媒体票据、分享会话和主动内容下载隔离。
- 状态候选提交、上一代恢复、fsync 与跨平台单实例锁。
- 内容寻址 Blob、逻辑文件独立、坏 Blob 恢复。
- 可验证备份与恢复回滚。
- 签名局域网发现、稳定身份、时效与确定性去重。
- 文档自动保存隔离、冲突草稿保留、上传并发限制。
- 版本统一、六目标构建、五轮重复核心回归。

## 测试结论

五轮全部通过：

1. 源码、版本、前端契约和核心回归。
2. 全包 Race Detector 和核心回归。
3. 安全/故障对抗与备份恢复。
4. 前端构建、六平台交叉编译和文件格式验证。
5. 安装包校验、真实 Linux 用户级安装/运行/卸载。

Go 总语句覆盖率为 **51.9%**，其中 API 52.5%、配置 71.2%、发现 32.1%、存储 49.9%。覆盖率没有达到稳定版要求，尤其 `main`、桌面启动与真实浏览器行为仍是盲区。

## 升级注意

- v1.2 明文 `access_key` 会在首次成功启动时迁移为 PBKDF2 派生值并从配置中移除。
- 默认监听已从所有网卡改为 `127.0.0.1`。局域网访问必须在设置强密钥后手动启用。
- 旧的 `?key=` 链接不再工作，前端会使用请求头或短时票据。
- 建议升级前备份整个旧数据目录，并在副本上验证恢复。

## 不应使用的场景

- 涉密或严格合规数据。
- 公网直接暴露。
- 多管理员或精细权限团队。
- 高频并发写入、十万级持续活跃对象。
- 要求无停机、集群、高可用或跨节点强一致的场景。
